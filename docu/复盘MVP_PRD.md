### §0.1.1 Q1 结论：T+1 离线（已定）

**问的是：算复盘的时候，昨天的数是不是已经"全了、定了"。**

| | **T+1 离线**（✅ 已选） | 盘中实时（本期不做） |
| --- | --- | --- |
| 什么时候算 | 第二天（或当日收盘后）一次性算完 | 交易进行中就边算边看 |
| 输入长什么样 | **一张已经落盘的完整实况表**（96 点齐全，Excel 文件就是终态） | **一条不断流进来的数据**，算的时候后半天还没发生 |
| 算完还用不用改 | 不用。算一次就是结论 | **要反复推翻重算**：14:00 看到的偏差，到 16:00 数据补齐后可能完全变样 |
| 报告怎么写 | 一份定稿 | 每一版都是"临时结论"，得标"截至 XX:XX" |
| 主要风险 | 数据口径是否与预测侧同源 | 数据迟到、重复到、后到把前面结论推翻 |
| 对本路线的影响 | A1 就是"读一张表 + 校验" | A1 要改成"流式接收 + 断点续算 + 版本滚动"，**整条链的时序假设要重写** |

**一句话**：T+1 是"第二天看昨天的账"，实时是"边打边算、算完还得改"。

**为什么 T+1 是对的，不只是省事**：复盘的价值在**归因**，而归因必须等实况齐了才成立——盘中电价还在动，"实际值"本身就不是终值，拿半成品当基准算偏差，等于拿未定的数当答案。复盘 PRD §7.1 亦明确"不做实时在线归因"。**盘中实时若以后要做，是新增一条路线，不是本路线的参数调整。**

### §0.1.2 Q4 带来的新边界：登记功能做什么、不做什么

**做**：只登记**两种结果**——成了的、报了没成的。**不记过程**（挂了几次、改了几次价、什么时候撤的）。

| 登记类型 | 记什么 | 用来回答什么 |
| --- | --- | --- |
| **已成交** | 运行日、时段、**成交价、成交量**、买卖方向 | 执行质量：成交价比市场高还是低、量够不够 |
| **报了没成** | 运行日、时段、**挂单价、挂单量**、买卖方向 | 机会成本：这笔没成，是错过了还是没赶上 |

> **这是 2026-10-21 追加的口径**，把原设计"只记成交"往前推了一步。原因很直接：**结果有两种，"成"和"没成"，只记一种就永远算不出"本来能赚多少"**。

**不做**：

| 不登记 | 原因 |
| --- | --- |
| **撤单原因 / 撤单时点** | 结果只有"没成"，撤单只是没成的一种，再细分对判断没有增量 |
| **挂单过程（挂了又改、改了几次价、什么时点挂的）** | 属盘中操作轨迹，复盘看落点；记这个会把录入负担压过登记率 |
| **未挂单的时段** | 空着标「未登记」，不推断成"没报"或"没做" |

> **"报了没成"要记的是"你报了多少价、多少量、最后没成"，不是"你为什么没成"。** 未成交的原因（对手方没量、排队没排上、价格被越过）复盘里一律不出结论，只提示核实。

**新增分析：未成交机会成本（估算，不是损益）**

| 项 | 定义 |
| --- | --- |
| 算什么 | 报了没成那部分，按**同时段现货（实时）电价**与你的挂单价的差 × 未成交量 |
| **前提（必须写进报告）** | **未成交量不消失**：滚撮卖不掉的电按**同时段现货（实时）电价**结算、买不到的量按现货价补。**所以只算"相对现货的溢价差"，不算整笔成交额**——按全额算等于把同一度电记两遍，会把 2,240 元放大成 6 万多 |
| 卖方口径 | `溢价未实现 = Σ(挂单价 − 该点现货价) × 该点电量`（该点电量 = 小时量 ÷ 4）。正数表示"为多要这点价，把本来能成的单挂飞了，只能按现货价卖" |
| 买方口径 | `多付溢价 = Σ(该点现货价 − 挂单价) × 该点电量`。正数表示"为少付这点价，没买到，只能按现货价补" |
| **时段与电量** | 登记粒度为 **24 点（小时）**，量以 **MWh** 记。**金额必须逐点结算、不做小时折算**（v1.2 修正，见下节 §0.1.2.1）：该小时 **4 个 15 分钟点分别与价相减、电量按 1/4 均摊、再累加**。**登记粒度仍是 24 点**——"登记粗、结算细"不矛盾：登记决定"填多少"，结算只读现货 96 点 |
| **负值怎么办** | 挂单价劣于现货价却没成交 → 实际结果反而更好 → 值为负。**照实呈现，不取绝对值、不写成损失、不并入正值合计** |
| **现货价缺失怎么办** | 该时段无实时电价 → **不出金额**，只记"未成交量"；**禁止用邻点价、区间均值、日前价替代** |
| **不含** | 手续费、偏差考核、后续补量成本、跨时段替代 |
| **称呼写死** | 一律写「**机会成本估算（溢价未实现）**」，**不得写成"亏损""盈亏""少赚了多少钱"**——它不是损益，是一次相对现货的价差 |

#### §0.1.2.1 已成交侧的逐笔收益（v1.2 新增，业务方 2026-10-22 拍板）

**原缺口**：§0.1.2 只定义了「报了没成」的机会成本，**已成交那一类只有价格和量、没有金额**——于是复盘能说"我在哪个点动了手"，却说不出"这一手值多少"。本版补上。

| 项 | 定义 |
| --- | --- |
| **结算本质（写死，不得改）** | **滚撮成交价是一小时的价**：该小时 **4 个 15 分钟点全部按这个成交价结算**；现货出清是 **96 点**，所以是**四个点各自与成交价相减、再按该点电量累加** |
| 卖方 | `已成交溢价 = Σ(成交价 − 该点现货价) × 该点电量` |
| 买方 | `已成交溢价 = Σ(该点现货价 − 成交价) × 该点电量` |
| 电量 | 该点电量 = 小时登记量 **÷ 4**（登记只到小时，无更细拆分；将来若登记到 15 分钟，直接换逐点电量、公式不变） |
| **禁止「代表价」** | **不得取小时均值、中位数、某一单点**当基准再乘整小时电量。三种做法在本项目内**已试过并全部作废**：8 月实测「部分点为负」的混合小时 **74 个**、整小时全负 **109 个**，取任一个代表价都会改变结论 |
| **实证（写进报告的口径说明）** | 8-14 15 时现货 `[295, −50, −48, 294]`，一笔 **283 元** 的成交：按均值 123 算 **+12,800 元**、按首点 295 算 **−960 元**、按逐点算 **+12,820 元** —— **三个数、两种正负**。这就是"必须逐点"的证据，不是风格偏好 |
| **逐笔表必须并列四列** | 「该小时 4 点现货」「逐点价差（4 个）」「量」「收益」，使读者**能手算复核**（4 个价差 × 1/4 电量相加 = 收益） |
| **缺值** | 4 点中**任一点**缺实时电价 → **该笔不出金额**（D-A9 `pnl` 置空），只记量与价，**禁止用邻点、区间均值、日前价替代** |
| **两类合计算法** | **已成交溢价合计**与**机会成本估算合计**是两行、**分开列**（各带笔数、电量；多日版还须带「其中为正几笔」）；**单日版可多给一行「两者相加＝当日执行溢价」**，含义是"卖侧高卖/买侧低买相对现货的执行好坏"，**仍不是损益**；**多日版不出这一行**（跨期相加会造出利润表的错觉） |
| **绝对不出的数** | 「本期一共赚了多少」「净收益」「利润」——**无成本、无结算、无手续费、无偏差考核、无回单**，五个口径全缺，这个数算不出来也不许暗示。命中即拒绝导出（见 §7.1 X-12 词表） |

> **为什么已成交和未成交要放在同一章**：它们是同一件事的两个结局。只列没成的，看起来像只有损失；只列成交的，看不出挂飞的代价。并排列出，才知道"同一时段我到底是买到了还是没买到、代价差多少"。

> **为什么不能合并成一个净额**：已成交是"真的成交了的价差"、未成交是"本来可以但没成的价差"，两者混加会造出一个看起来像利润表的数。**要看全景就并排看，要判好坏就一句一句说。**

**红线（一条收窄，其余不变）**：

| 禁止 / 允许 | 说明 |
| --- | --- |
| ❌ 系统生成或推荐挂单价 | 复盘 PRD 红线：不代拟报价 |
| ❌ 系统推算"如果你挂 X 元就能成" | 反事实报价建议，越界 |
| ✅ **允许**：对**已经发生**的挂单算机会成本估算 | **v0.5 的收窄**：原"不算盈亏"针对的是"没有回单、没有成本口径的损益核算"，不是"不许算机会成本"。**只算价差 × 量，不建损益账、不出财务报表** |
| ❌ 用登记数据出正式损益报表、贴"盈亏"标签 | 无成本、无结算、无回单，算不出真盈亏 |
| ❌ 把登记值当"客观事实" | 它是交易员自述，**置信度低于回单**，报告必须标注 |

**这条边界为什么必须现在写死**：登记表一旦存在，"顺手做个挂单价建议"是最容易发生的一次越界——数据都在手边，做个"参考价"看起来只差一步；再往前一步，就会变成"你上周少赚了 12 万"。**前者越权，后者算不准却最难反驳。登记是记账，不是决策。**

> **`value_type` 定为"不改，维持七种"（2026-10-21 按代码核实后改定；原拟"新增第八种 `登记`"作废）**：`value_type` 是 `boundary_master` 的列，只描述"边界值怎么来的"；成交登记在 D-A9，自带 `result_type ∈ {成交, 未成交}`，**两者不是一类对象**。`意向`（一阶段 M5 录入的"想报的价"）与"实际报了/成了"确实必须分开——但分开的方式是**另立对象**，不是往共用枚举里加值。两种坏结局见 §0.1.4 回写清单第 1 项。

### §0.1.3 「当时预测价」落档：对现有程序的改动（Q2 的落地含义）

复盘要回答"当时我怎么判断的"，就必须要**当时那条 96 点预测价**。当前程序的落档情况是**一半有一半没有**：

| 落什么 | 现在在哪 | 状态 |
| --- | --- | --- |
| 交易员改之前（系统原值） | `boundary_master`（`store.py:71`） | ✅ 按 `run_id` 存，不覆盖 |
| 交易员改之后 | `boundary_revision`（`store.py:80`） | ✅ append-only，`prev_rev_id` 串成链，改几次都在 |
| 复盘取哪个值 | `effective_value(run_id)`（`store.py:98`） | ✅ 读时合并：最新有效修订 > 主表原值 |
| **火电开机（M7）** | — | ❌ **不落库**，`BOUNDARY_WHITELIST` 只有 9 个输入边界（`pipeline.py:28`） |
| **风机负荷率（M7）** | — | ❌ **不落库** |
| **预测电价 96 点（M8）** | — | ❌ **不落库**，`api.py:217` 是调用时现算 |
| 预测联络线（M6） | — | ❌ **不落库** |

**所以"复盘直接调取"这句话，对边界值成立，对预测结论不成立**——库里只有配方，没有做出来的菜。

**本期要对现有程序做的改动（三项，全部属增量，不改动已有口径）**：

| # | 改什么 | 具体动作 |
| --- | --- | --- |
| ① | **新增快照表 `calc_snapshot`** | 字段：`run_id`、`seq`（同日第几次算）、`date`、`t`（1–96）、`item`、`value`、`params_json`、`code_version`、`created_at`；唯一键 `(run_id, seq, item, t)`。**落全链关键输出**：M6 预测联络线 96、M7 开机 96、M7 负荷率 96、M8 电价 96 |
| ② | **落档时点与次数** | 每次 `recalc()` 完成后写一次；**与是否发起复盘无关**（否则事后补录拿不到当时值）；同日多次重算按 `seq` 递增**各自留一份**，后者不覆盖前者 |
| ③ | **修两个"名存实亡"的字段** | `calc_run.params_snapshot` 现在硬编码 `DEFAULT_PARAMS.as_dict()`（`pipeline.py:184`），**存的是默认值而不是实际生效参数**；`boundary_master.calc_version` 被赋成 `run_id`（`store.py:76`），**不是版本号**。两者都改成真值，否则快照带不出"当时用的什么" |

> **为什么这三项必须现在做**：没有快照，"当时预测价"只能靠今天的代码重算；算法一升级，重放出来的就不是当时那条线，而且**差额不可观测**——不是差一点，是没有任何记录能告诉你差多少。
>
> **取数硬规则（同期定死）**：报告所有数字**只读快照、永不重算**。快照缺项就写"该项未落档"，**不许拿重算值顶上**。这条同时减轻 T-6（证据包逐字段复现）的压力——重算才需要担心浮点序与版本漂移。
>
> **历史 8 月已经跑过、没有快照的日子，只能重放**，报告一律标注「**重放值，非当时值**」，不得用于"当时我怎么判断"这类结论。8 月 31 天在本期仅作版式与算法演示样本。

### §0.1.4 与上游 PRD 的衔接缺口：成交登记为什么放在这里做

**缺口不是"复盘 PRD 少写了一段"，而是一阶段决策链的产出到复盘之间断了一节。**

| --- | --- | --- | --- |

## §1 描述技术路线


### 1.1 技术路线一句话

**用"当时那套参数"把预测链原样重放成基线，再用 8 次全链重算（1 次全实况 + 7 次单因子替换）把电价落差拆成各项边界的贡献与残差；残差按三类跃变定性，定性不了就只提问不归因；成交侧暂时没有回单，改由交易员**登记"成了的"与"报了没成的"两类结果**自建一条基准流，既能评成交质量、也能估未成交的机会成本；所有数字封进一个带编号、可逐字段复现的证据包，大模型只按四段写解释、不碰算术；最后代码排骨架、校验数字、导出 Markdown 报告，全过程 append-only 留档，供跨日统计三画像、补偿有效性与习惯。**

这句话里有五个可以被单独打问号的地方：**基线能不能复原到"当时"**（r11 已查明——**不是复原问题，是落档问题**：边界值改前改后本就完整落库，缺的是 M6/M7/M8 输出没落，见 §0.1.3）、**单因子能不能解释掉大部分落差**、**证据包能不能做到 100% 可复现**、**归因结论能不能与人判一致**、**手工登记的成交数据够不够用**。第 2 步按"一条判据一个 T 号"把它们连同另两处一起拆开，**最终有效 12 条**——上面这几句是粗分类，不是最终编号。

### 1.2 为什么选这条

**它直接验证的主指标是 P-A0「证据包可复现率 = 100%」。** 选它当主指标，不是因为它最容易过，而是因为**整条路线的前提都压在它上面**：只要证据包不能 100% 复现，"AI 只解释、不做算术"就无从校验，后面 P-A1 溯源、P-A2 方向一致、P-A6 报告数字一致全部失效。换句话说，**这条路线成不成，先看证据包稳不稳**。

覆盖的关键环节是**后半条链的全流程**，而不是单点技术验证：

| 要验证的东西 | 主指标 | 本路线哪一段直接产出 |
| --- | --- | --- |
| 数字能不能被复现 | **P-A0 = 100%** | 环节 E 证据包 |
| AI 会不会越界做算术/编原因 | P-A1 ≥95%、P-A2 = 100% | 环节 F 归因（**本期直连真模型**） |
| 真模型跑得完、跑得起 | P-A3 单日 ≤30 s | 环节 F + G（接入真模型后由"预期"变成"待实测"） |
| 报告里的数字能不能对上 | P-A6 = 100%（不过则拒绝导出） | 环节 H 导出（`.md` / `.csv`） |
| 规律到底是真规律还是幻觉 | P-A4：31 天 ≥1 项显著，**或**明确判定样本不足 | 环节 G 统计 |
| 交易员自报的成交数据能不能当基准 | **P-A10（本期新增，第 3 步定阈值）** | 环节 A2 登记 → C 对账（**只对"成了什么"，不对"为什么没成"**） |

**与 R-RP 的取舍（一句话）**：R-RP 的反事实对象是**边界输入**（2⁷ 组合，128 次全链/日），本路线的反事实对象是**预测值 vs 实况值**（8 次全链/日）。**成本降一个量级，代价是放弃"组合穷尽"**——组合不唯一时只能给"多项共同作用"的诚实结论，用缺口倒推（1~3 次验证）替代枚举。

> **不在这里重复"为什么不用纯 AI"**：那三条硬伤（算错、不确定、幻觉）已在复盘 PRD §1.2 论证完毕。本文件只接它的结论：**计算归代码，解释归模型**。

### 2.1 两把尺子：试金石与风险等级

**试金石＝三道闸，任一不过即不得写入。**

| # | 闸门 | 问法 | 被它挡掉的是什么 |
| --- | --- | --- | --- |
| ① | **答案是否已经知道** | 不做实验，我能不能说出结论？ | 已实测过的（实况齐不齐＝100%）；模型里根本做不到的（上临界反算缺口） |
| ② | **是不是"做完即知"的工程量** | 做法已经清楚，只是还没动手？ | 字段映射、色带在下层、占位符替换——做完就有答案，做之前已知道怎么做 |
| ③ | **不过是否只落在"改代码重跑"这一层** | 不过之后除了修代码、重跑、再核，还有没有别的后果？ | 纯实现缺陷：修完就好，不改变路线，也不改变结论形态 |

> **三闸的意义是防两类冒充**：把"还没动手的活"写成不确定点（虚增），把"其实做不到的功能愿望"写成不确定点（画饼）。**过闸的只剩一类：不做实验，我真的不知道结果会怎样，而这个结果会改变路线怎么走。**

**风险等级只按后果分三级，不猜通过概率**（理由：概率是拍脑袋，且会诱导"按概率排优先级"，把低概率的阻断项往后排）。

| 等级 | 定义 | 条数 |
| --- | --- | --- |
| **阻断** | 不过则路线不成立，必须换形态或换路线 | 1（T-6） |
| **高** | 路线能跑完，但主指标不过，交付必须退一档 | 8（T-1、T-2、T-3、T-4、T-7、T-9、T-10、T-13） |
| **中** | 局部降级：某一章或某一类结论作废，主线照跑 | 4（T-5、T-8、T-11、T-12） |

## §4 备选路线（第 4 步）

### 4.1 退路编号与三条切换纪律

**编号**：退路用 **B-x**，与 T-x **一一对应**（B-1↔T-1 … B-13↔T-13；T-2/P-2 已作废，B-2 同）。

**退路只有两种形态**，不存在第三种：

| 形态 | 定义 | 判据 |
| --- | --- | --- |
| **局部降级** | 只动一个环节或一类结论，其余九环节照跑、报告照出 | 砍掉后**其余章节仍能成立** |
| **换技术路线** | 整条路线的核心机制不成立，必须重议形态 | 见 **§4.4**，本期只有两个触发条件 |

**三条纪律（先写死，防"降级"变成"躺平"）**

| # | 纪律 | 怎么执行 |
| --- | --- | --- |
| ① | **修复最多两轮，且第二轮必须是不同根因** | 一轮修复 = 四件套：**根因属于哪一类／改了什么／重测结果／判定人签字**。**同一根因不得修第二轮**——这是"修复"与"再试一次"的唯一分界线 |
| ② | **修复成功必须回退到更高档** | 走降级档后若根因查明并修好，**必须退回原档重测**，不得停在降级档凑合。停在降级档 = 把可修的工程 bug 记成路线缺陷 |
| ③ | **降级要写代价，换线要写触发** | 每一档退路都写清"损失了什么"（少一章／少一类结论／失去什么能力）；换线只认 §4.4 的两个条件，**其余 11 条一律不触发换线** |

### 4.3 逐条退路（四段式：触发 → 修复 → 退路 → 代价）

#### B-1 ↔ T-1　自报登记能否当成交侧基准｜局部降级

| 项 | 内容 |

| **触发** | P-1 不通过（拦截率 <100%／误拦率 >0／算术一致率 <100%／量级偏离中位 >30%） |
| **先做（修复，最多两轮）** | 轮① 核对**量的口径**：登记量含不含代理电量、含不含未出清部分，与省间量的定义对齐后重跑；轮② 核对**时段对齐**：登记 24 点 ↔ 证据包 96 点的映射是否错格，修正后重跑 |

#### B-3 ↔ T-3　单因子贡献能否加总还原总落差｜局部降级

| 项 | 内容 |
| --- | --- |
| **触发** | P-3 不通过（`explained_ratio` 中位 <70% 或 P10 <50%） |
| **先做（修复，最多两轮）** | 轮① 查残差最大的 5 个点是不是落在**临界段**或**非线性段**（如贴下限、开机跳变），若是则改为**分段**计算贡献；轮② 把"单因子替换"改成"成对替换"（`c_b` 按对称差分算），成本由 8 次全链/日升到 15 次/日 |
| **退路 D1** | **不给各项占比**，只给"按贡献排序 + 方向（同向/反向）"，并在表头写死「各项贡献不可加总，不构成占比」 |

| **换线** | 否 |

> **为什么不换到 R-RP**：R-RP 的反事实对象是**边界输入**（2⁷ 组合，128 次全链/日），它解决的是"组合不唯一"，**不是"残差解释不了"**——残差来自模型非线性，换 128 次也一样解释不了。换线成本涨一个量级，买不到这个答案。

#### B-4 ↔ T-4　类型三与口径差能否分开｜局部降级

| 项 | 内容 |
| --- | --- |
| **触发** | P-4 不通过（`Kappa <0.6`，或一致率 <80%，或误判天数 >1） |

| **换线** | 否 |

#### B-5 ↔ T-5　缺口倒推能否把组合降到唯一｜局部降级

| 项 | 内容 |
| --- | --- |
| **触发** | P-5 不通过（一致率 <80%） |

| **退路 D1** | 一律写「**多项共同作用**」，并**列出候选集合**（哪几项、各自方向），**不得硬给单因** |
| **退路 D2** | 跃变日**单独走成对枚举**（即 R-RP 的核心手段），只在跃变日启用，非跃变日仍走缺口倒推 |

| **换线** | 否 |

> **D2 不是换线**：成对枚举在这里是**一个环节内的局部手段**，只用在跃变日，其余八环节与 31 天里的非跃变日照跑原路线。**"局部借用另一条路线的手段"与"换整条路线"是两回事**——后者才是 §4.4 管的。

#### B-6 ↔ T-6　证据包能否 100% 逐字段可复现｜**三级降级**（唯一阻断项）

### 4.4 换整条技术路线的唯一触发条件

| 条件 | 内容 |
| --- | --- |
| **A** | **T-6 走完 D1／D2／D3 三级仍不过**——证据包即便只封关键量、也做不到稳定复现 |
| **B** | **T-12 中 6 份报告有 ≥2 份走到 D2（拒绝导出）**——H 环节作为终点环节交付不出去 |

**动作**：不预写替换方案，回上层重议形态，由业务方拍板后另立验证。

> **R-RP 不是 T-6 的退路，这点必须写死。** R-RP 是**重放枚举式**，它比本路线**更依赖**"重放可复现"——证据包复现不了，R-RP 的 128 次重算只会错得更彻底。所以条件 A 触发时**换线不等于"改走 R-RP"**，而是回到形态层面重议（可能的方向：砍掉大模型环节、改为纯确定性代码报告、或接受人工复核为正式形态）。
>
> **除 A／B 外，其余 10 条不论退到第几档都不换线。** 一条 T 号挂一个换线条件，等于给每一次局部失败都开一张"整体重来"的口子——那正是本节要防的。

### 4.5 走退路之后怎么下结论

| 走了什么 | 结论 | 报告里必须写什么 |
| --- | --- | --- |
| **一条都没走** | **通过** | 无附加说明 |
| **走过 D1／D2／D3 任一档，未触发 §4.4** | **有条件通过** | 逐条写明：哪一条、退到第几档、**损失了什么**（少哪一章／少哪类结论／失去什么能力）；已修复并回退的也要记一笔（纪律②） |
| **触发 §4.4 条件 A 或 B** | **不通过** | 回上层重议，本文判定到此完成"这条路走不走得通"的回答 |

## §5 最小功能范围（第 5 步）

### 5.1 挑选口径：不设计功能，只从 X-A 里挑

三条不越界：

| # | 约束 | 怎么执行 |
| --- | --- | --- |
| ① | **不新造功能** | 每个模块必须指到上游 `X-A1`～`X-A33` 的某一条；**唯一例外是成交登记**（上游无对应条目），必须显式标「范围净增」并说明来源（Q4 业务方新增） |
| ② | **不砍验证必需** | 凡被某条 `P-x` 的判据直接取数的模块，一律不得移出本期 |
| ③ | **不越铺越大** | 业务方点名要的（界面、习惯）可以进，但**每进一项都要标明它服务谁**，且不得顺手带出关联功能 |

**口诀「没有它，还能验证吗」**：

- **能验证** → 可以不进最小范围；
- **不能验证** → 必须留。

> **口诀只判"验证必需"，不判"业务方想不想要"。** 界面与习惯都属于"没有它也能验证"——业务方已定要做，所以它们在清单里，但标注为「**业务要求，非验证必需**」。**这个标注必须留着**：日后界面做得不好，不能被读成"技术路线没走通"；反过来，也不能因为界面在，就顺手把验证结论的锅甩给它。
