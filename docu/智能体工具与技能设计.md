# 智能体工具与技能设计

> 本文档是 Step 6/7/8 的实现契约：工具注册表（10 工具）+ 5 个 skill 拆分 + 交互模式。与 `docu/交易员计算流程与逻辑.md`（计算口径）配套；口径冲突以 PRD 为准。

## 1. 双层架构

- **产品运行层**：M9 工作台右栏助手 = LLM（OpenAI 兼容 `/chat/completions`）通过 **function calling** 调用 Python 工具（`backend/llm/tools.py` 注册）。**确定性算术永远在 Python 工具内执行，LLM 不做算术**——LLM 只决定调哪个工具、如何组织回答；一切数值来自工具返回，回答需引用工具返回数值、禁止编造。
- **开发层**：`.agents/skills/` 下 5 个 `roll-auction-*` skill，供 omp agent 开发/改码时按模块加载（正文=对应模块算式精简版，链接口径文档与 PRD 锚点）。
- 两层共用同一模块分解（`backend/modules/` ↔ skill ↔ 工具）。

```
用户（右栏对话框）
  │ 自然语言 + 当前时段上下文（自动装载）
  ▼
/api/chat ──► llm/client.py（function-calling 循环，单轮 ≤8 次工具调用）
  │            │ tools（JSON Schema，由 llm/tools.py 注册）
  │            ▼
  │        pipeline / store（确定性计算 + 留痕）
  ▼
回答（引用工具数值）+ chat_log 快照留痕
```

## 2. 工具注册表（`backend/llm/tools.py` 实现；OpenAI tools JSON Schema）

| # | 工具 | 参数 | 返回 | 说明 |
|---|---|---|---|---|
| 1 | `get_state` | `period?: int`（1–24） | 工作台快照：边界/参数/意向/全链输出（可按时段裁剪）+ 数据就绪清单 | 问答类 |
| 2 | `run_chain` | — | 触发 M1→M8 全链重算；返回各模块状态与耗时 | 跑流程类 |
| 3 | `set_params` | `params: object`（键=参数名，值=数值/数组） | 校验结果 + 联动重算后的关键输出摘要；非法（区间宽度非正整数、意向价 ≤0 等）返回错误 | 改数据类；校验规则见 §5 |
| 4 | `modify_boundary` | `boundary: string`，`period: int`，`points: [{t:int, value:number}]`（t=1–96），`reason: string` | 修订记录（rev_id）+ 下游联动重算摘要；`reason` ≥5 字强制 | 改数据类 |
| 5 | `set_intent` | `period: int`，`list_price?: number`，`lift_price?: number`，`volume?: number` | 意向录入结果 + 灰度量价联动 | 改数据类；价 >0 校验 |
| 6 | `get_module` | `module: 'm1'…'m8'`，`period?: int` | 模块输出 + 推导理由：样本组成员/基线算式/开机中间值/拟合系数 M1C1·M2C2/临界空间 | 问答类 |
| 7 | `search_similar_days` | `period: int`，`threshold?: number` | 相似日成员 + 负荷率对比表 + N/分子/分母/统计范围 | 跑流程类 |
| 8 | `explain_period` | `period: int` | 该时段决策依据链：输入 → 中间值 → 结论（含落点概率/灰度） | 问答类 |
| 9 | `rollback_revision` | `rev_id: string` | 回退结果（回退本身记新修订） | 改数据类 |
| 10 | `export_report` | — | 触发表格/对照件导出，返回文件路径 | 跑流程类 |

参数命名与类型即 API 请求体契约；`period` 一律 1–24（时段），`t` 一律 1–96（点位）。

## 3. 交互模式约定（写进助手 system prompt 与本文档）

| 模式 | 工具 | 约定 |
|---|---|---|
| 问答 | `get_state` / `get_module` / `explain_period` | 数值全部取自工具返回，回答引用之 |
| 跑流程 | `run_chain` / `search_similar_days` / `export_report` | 返回状态与耗时，不代用户决策 |
| 改数据 | `set_params` / `modify_boundary` / `set_intent` | **必须先复述改动内容，要求用户给出 ≥5 字理由**；理由不足 → 拒绝并说明 |
| 评审 | （只读工具） | **只评审不代拟、不产可申报数值（护栏 G4）**；给风险提示与量价评审，不替交易员决定申报量价 |

- 每轮工具结果进对话上下文；单轮最多 8 次工具调用（超出 → 提示用户简化请求）。
- 每次助手回答（含工具调用序列、时间、版本）落 `chat_log`（快照留痕，D15）。
- 请求自动装载当前所选时段上下文（切换时段随切换，§5.4b 口径）。

## 5. 参数校验规则（`set_params` / `set_intent` / `modify_boundary` 共用）

- `reason` / 备注：≥5 字（中文字符计 1）。
- 意向挂牌/摘牌价：数值且 >0。
- 交易量：数值且 >0。
- 现货上限 > 现货下限；区间宽度 = 正整数；±5% 阈值 ∈ (0, 1]；零价点负荷率 ∈ (0, 2]；调频/正备用/负备用 ≥0；受阻系数 ∈ [0, 1)；装机/最小开机/检修 ≥0。
- `boundary` 白名单：省调负荷/风电/光伏/水电/核电/地方燃煤/非市场化/联络线（+ 火电开机走 M7 双模式，不直接改边界）。
- `t` ∈ 1–96、`period` ∈ 1–24、value 为有限数值。
- 非法 → 返回结构化错误（字段 + 原因），不落库不重算。

## 6. LLM 接入口径

- OpenAI 兼容 `POST {LLM_BASE_URL}/chat/completions`，携带 `tools`（§2 注册表）与 `tool_choice: "auto"`。
- 配置三要素：`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（`.env` 或 `POST /api/llm/config` 运行时写入；key 只存 `.env`/内存、不回显、不入库不入 git、不打日志）。
- base_url 可指向 OpenAI/DeepSeek/GLM/Qwen 或内网网关（可配优先可用性，不硬限制内网）。
- 无 key / 网络错 → 结构化错误信息给前端（含配置引导），不抛裸异常。
- function-calling 循环：工具结果以 `role:"tool"` 回填后继续请求，直到产出最终回答或达 8 次上限。
